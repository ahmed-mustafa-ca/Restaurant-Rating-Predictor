# Restaurant Rating Predictor

A machine-learning project that estimates a restaurant's aggregate rating from its location, typical cost, service options, and cuisine. Model development is documented in a Jupyter notebook, and a Streamlit app provides an interactive interface for rating predictions.

## Problem

Given a restaurant's attributes, predict its numeric aggregate rating on the dataset's 0-to-5 scale. This is a **supervised regression** problem because the target is numeric.

The supplied CSV contains 9,551 restaurant records. Rows with an aggregate rating of `0` and a `Rating text` of `Not rated` represent restaurants without a rating, not restaurants with a genuine zero score. They are excluded from model training. The notebook also excludes `Rating text` and `Rating color` from the predictors because they are derived from the rating and would leak target information.

## Features used

The model uses these seven input features:

| Dataset column | Meaning |
| --- | --- |
| `City` | Restaurant's city |
| `Locality` | Neighborhood or locality |
| `Average Cost for two` | Reported average cost for two people |
| `Currency` | Currency associated with the cost |
| `Has Table booking` | Whether table booking is available |
| `Has Online delivery` | Whether online delivery is available |
| `Cuisines` | Restaurant cuisine field |

`Aggregate rating` is the prediction target, not an input feature.

## Project workflow

The notebook follows the requested machine-learning workflow:

1. Load and inspect the supplied CSV.
2. Clean the data, coerce numeric fields, and exclude unrated rows.
3. Explore rating distributions, costs, and city-level statistics.
4. Prepare the selected features and split data into training and test sets.
5. Build preprocessing pipelines: impute missing values, standardize the numeric cost feature, and one-hot encode categorical features. Unseen categories at prediction time are supported.
6. Compare a mean-prediction baseline, Ridge regression, and Extra Trees regression.
7. Tune Ridge and Extra Trees with cross-validation on the training data.
8. Evaluate the selected model on the held-out test data using MAE, RMSE, and R².
9. Save the complete fitted preprocessing-and-model pipeline and metadata.
10. Define FastAPI health and prediction endpoints in the notebook.

The model-selection and hyperparameter-tuning stages use training data only; the held-out test set is reserved for final evaluation. The saved model is a Ridge regression pipeline selected by cross-validation.

## Setup

Use the same Python environment for the notebook kernel and the project commands. From the project folder, install dependencies:

```bash
python -m pip install -r requirements.txt
```

In Jupyter, open `notebook.ipynb` and run the cells in order. The notebook expects `Dataset .csv` to be in the same folder and generates `restaurant_rating_model.joblib` and `restaurant_rating_metadata.json`.

If a notebook cell reports that a package such as `joblib` is missing, install requirements into the **active notebook kernel** using:

```python
%pip install -r requirements.txt
```

Then restart the kernel and rerun the notebook cells.

## Run the Streamlit interface

After generating the model and metadata files:

```bash
streamlit run app.py
```

The app lets a user choose a city, locality, currency, booking and delivery availability, and cuisine, and enter an average cost for two. It displays the model's estimated rating. The prediction is an estimate based on historical data, not a guarantee of a restaurant's actual rating.

## FastAPI

The notebook defines a FastAPI application as `app` (also named `api`) with:

- `GET /health` — basic service health and model-file presence.
- `POST /predict` — validates restaurant feature inputs and returns a predicted rating.

The server-start cell runs Uvicorn from the notebook kernel. Run the model-saving cells first, then execute the API definition and server-start cells. The server listens locally at `127.0.0.1:8000`. FastAPI is included as a separate API option; the Streamlit interface currently predicts directly with the saved model.

Example request body for `/predict`:

```json
{
  "city": "New Delhi",
  "locality": "Connaught Place",
  "average_cost_for_two": 1200,
  "currency": "Indian Rupees(Rs.)",
  "has_table_booking": "No",
  "has_online_delivery": "Yes",
  "cuisine": "North Indian"
}
```

## Evaluation

In the validated run on the supplied data, the tuned Ridge pipeline achieved:

| Metric | Test result |
| --- | ---: |
| MAE | 0.302 |
| RMSE | 0.392 |
| R² | 0.491 |

Metrics may vary if the data, split, dependencies, or training procedure changes. MAE and RMSE are measured in rating points; lower values indicate smaller prediction errors. R² describes fit relative to predicting the target mean.

## Limitations and considerations

- The model reflects the supplied dataset and its geographic and rating distributions; performance may differ for new locations, cuisines, or time periods.
- Average costs are paired with a currency feature; cost values are **not** converted to a common currency.
- Cuisine is treated as a categorical field as recorded in the source dataset.
- The Streamlit selectors use categories observed in the training data. The model pipeline can handle unknown categories, but the UI does not provide free-text entry for those fields.
- Votes are not included among the selected features.
- Retrain and reevaluate the model when updating the dataset or changing the feature set.
